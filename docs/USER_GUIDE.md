# Frameflow 使用说明书

## 1. 安装与打开

先安装 Node.js 20.19+ 或 22.12+。在终端执行：

```bash
git clone https://github.com/Karen0758/frameflow-scroll-story-workbench.git
cd frameflow-scroll-story-workbench
npm ci
npm run dev
```

浏览器打开终端打印的本地地址。工作台需要现代浏览器的 IndexedDB、Canvas、CompressionStream；建议先用最新版 Chrome 或 Edge。`npm run build` 可以检查代码并生成工作台静态文件 `dist/`；`npm run preview` 预览该构建。

## 2. 从空白项目开始

1. 顶部改「项目名称」。左栏点击「＋ 添加新场景」，用「前移 / 后移」设置滚动顺序。也可以导入仓库内的 `templates/starter.frameflow`。
2. 右栏「页面」编辑场景名称、标题、正文和底色。正文中的换行会被保留。
3. 选择进场效果：波浪、正圆扩张、整页滑动或渐显。圆形可以改圆心，滑动可以改方向。设置过场时长、人物开始和文字开始，单位是毫秒。
4. 「风格」选择文字色、强调色，以及衬线或无衬线字体气质。正式网站的授权字体需在网站实现时另行接入。
5. 在画布上拖动人物和文字，也可在右栏输入 X、Y、宽、高。切换「电脑 / 手机」后分别调整：当前设计画布为 1440×900 和 390×844，不会自动把电脑位置等比复制到手机。
6. 点「播放交互」预览；滚轮向下/向上或触摸滑动可切页。拖动底部时间线可以查看当前场景的关键时刻。

## 3. 导入人物与背景

在「素材」页，为**当前选中的场景**上传图片：

- 「上传透明逐帧图」：适合已经去背的人物、印刷阴影和其他独立主体。多选的图片按文件名自然排序，因此建议命名 `actor-001.webp`、`actor-002.webp`……。一次最多 120 张，画布像素尺寸必须完全相同。
- 「上传背景纹理」：给当前场景添加一张材质图。若希望人物吸收底色，请使用灰度透明人物帧，再到「页面」里选择 Multiply；不要在人物帧里预先画入目标颜色。
- 「从视频抽帧」：选择本地视频、开始/结束秒数、帧率和输出宽度。工作台按源视频比例计算统一高度，生成 WebP 并直接应用到当前场景。默认宽 720 px、12 fps，最多 120 张；输出画质固定为 0.84。若过长，请缩短动作区间或降低帧率。

**视频抽帧保留原背景。** 需要纯人物层时，请先用其他工具去背，再上传透明序列。工作台目前也不对人物逐帧自动居中或校正缩放；原视频若有推拉镜头，先在素材处理阶段统一人物脚底位置和视觉大小。

## 4. 检查视频帧

在正式使用逐帧图前检查首帧、中间动作帧、尾帧及动作交接处：

- 头顶、两只鞋、鞋尖和印刷阴影均在每帧画布内；不能靠网页放大或层级设置修复已被切掉的部分。
- 同一序列所有帧的宽高、脚底基线和人物视觉大小保持稳定；首尾动作不要突然跳帧。
- 阴影方向和接地位置连续。当前每屏只有一个人物图层；需要保留印刷阴影时，请把它和人物一起放在同尺寸透明帧中。
- 用目标背景试播 Multiply；若上传的是白底视频截帧，白色仍属于图像像素，会盖住纹理，应先去背。
- 观察图片总量。三组动画会累计占用浏览器存储与首屏带宽；以最小可接受宽度、动作区间和帧数取舍，再在目标设备检查清晰度与加载。

## 5. 保存、迁移与恢复

编辑会自动保存：项目配置在浏览器 `localStorage`，媒体在 `IndexedDB`。**此保存只属于当前浏览器配置文件**，清除网站数据或换电脑可能丢失。每完成一个可用版本，点「导出可编辑项目」保存 `.frameflow`，它同时包含配置与媒体。另一台电脑点击「导入项目包」即可继续编辑。导入会替换当前项目；先导出旧项目备份。

`templates/scroll-story.example.json` 是未来结构草案，**不能作为当前项目包导入**。

## 6. 把网页交付给别人

工作台提供两种不同文件：

| 文件 | 用途 | 可以直接交给网站访客吗？ |
|---|---|---|
| `.frameflow` | 保存场景配置和图片，供工作台再次导入编辑 | 不可以，它不是网页 |
| `-website.zip` | 独立静态网页；含 `index.html`、`assets/` 和 `README.txt` | 可以，解压并部署后访客可上下滑动浏览 |

操作步骤：

1. 完成人物、背景、文字和电脑/手机布局后，先点「导出可编辑项目」留一份备份。
2. 点「导出网页 ZIP」，解压下载的 ZIP。在解压目录运行 `python3 -m http.server 8000`，再访问 `http://127.0.0.1:8000/` 本地预览。
3. 把**整个解压目录**上传到静态网页托管空间，确保 `index.html` 位于网站根目录，`assets/` 与它在同一级。不要只上传 `index.html`，否则人物和纹理无法加载。
4. 打开实际访问网址，在电脑和手机分别检查：向下进入下一屏、向上回退、人物首尾帧、页面过场、文字可读性与素材加载速度。右下角「继续下滑」是提示文字，没有点击功能；到最后一屏会隐藏。

导出的 ZIP 是展示版，不会把编辑器或 `.frameflow` 文件暴露给访客。当前没有一键绑定域名或上传到托管平台的功能。素材未获授权时不要公开上传。

## 7. 使用 Skill

Skill 放在 [`skills/frameflow`](../skills/frameflow/SKILL.md)。在 macOS/Linux 的 Codex 环境，可用：

```bash
mkdir -p ~/.codex/skills
ln -s "$(pwd)/skills/frameflow" ~/.codex/skills/frameflow
```

如果目标路径已存在，先检查它，避免覆盖。之后在 Codex 新聊天中输入例如：「用 `$frameflow` 帮我把这段视频做成三屏逐帧网页样稿；我有两张纸纹背景，请先检查头脚与影子。」Skill 负责引导制作与验收；实际编辑器仍由本仓库运行。它不会自动上传素材或替你发布网站。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 视频无法读取 | 先确认浏览器能直接播放该文件；转成常见 H.264 MP4 再试。|
| 导入图片提示尺寸不统一 | 用相同宽高的透明画布重新导出所有帧。|
| 动画一开始像停住 | 检查视频开头是否有静帧；调大抽帧开始秒数，重新生成。|
| 人物边缘/影子断裂 | 查看源帧是否已截断；修正素材，不能仅调 CSS。|
| 人物被背景盖住 | 检查是否上传了不透明原视频帧；使用透明人物帧，并选择合适混合模式。|
| 手机画面重叠 | 切到手机画布，单独调整文字和人物的位置与大小。|
| 项目在另一浏览器不见了 | 从导出的 `.frameflow` 文件导入；本地自动保存不会跨浏览器同步。|
| 解压后人物/背景不显示 | 确认 `assets/` 文件夹和 `index.html` 一起保留，并原样上传。|

## 9. 能力边界与发布

这个版本交付**可编辑项目包、工作台预览和独立静态网页 ZIP**。它没有自动抠像、影子修复、账户协作和云端发布；导出的网页也不支持服务器端功能。若要做正式官网，还需要按项目要求补充品牌字体、导航、表单及其他功能，并分别检查构建、本地浏览器和线上 URL。
