# 逐帧叙事官网：项目模板与工作台蓝图

这份模板从 SIX 官网提炼，适用于「一屏一个场景，滚动或滑动切页，人物动作与色块转场配合」的网页。新项目请先填写 `templates/NEW_PROJECT_BRIEF.md`，再在 Frameflow 工作台内建立页面。下方 JSON 是未来数据结构草案；**当前 SIX 网站和 Frameflow 都不能直接导入该 JSON 运行**。Frameflow 使用自己导出的 `.frameflow` 项目包往返编辑，并可单独导出静态网页 ZIP。

## 1. 新项目先填写什么

| 项目项 | 填写内容 | 验收标准 |
|---|---|---|
| 品牌 | 名称、受众、基调、字体授权、主色与纸纹/其他材质 | 不依赖图片也能识别视觉方向 |
| 页面 | 首页及后续场景的顺序、标题、正文、按钮、联系入口 | 每一页都有明确内容与下一步 |
| 人物 | 每页人物的首帧、动作、尾帧、阴影方向和画面锚点 | 头、脚、影子在全程完整连续 |
| 触发 | 点击人物/色块/文字、向下进入、向上返回 | 鼠标、触控板、手机触摸可达到同一页面 |
| 转场 | 形状、起点、方向、时长、缓动，以及人物/文字的开始时刻 | 动画结束时目标底色铺满视口，不留角落残片 |
| 适配 | 桌面和手机的构图、文字区域、可滚动正文 | 人物不遮字，文字可读完，不误触切页 |
| 发布 | 素材许可、目标域名、代码和媒体的发布方式 | 构建、浏览器和线上地址分别验收 |

## 2. 标准制作流程

1. **画场景表。** 先定每一屏的内容和「上一屏 → 下一屏」关系。首页可有多个入口，但滚动顺序必须唯一；有长正文时，先滚完正文再切页。
2. **做分镜和时间轴。** 把「离场底图、目标底色、人物、文字」画成独立轨道。记录各自从第几毫秒启动；不要用单个总时长代替这些关系。
3. **处理视频素材。** 保存原视频，确认帧率和时长；选动作区间，抽帧、去背景、统一画布尺寸和脚底锚点，校正镜头缩放，保留或修复连续的真实阴影。逐帧检查头顶、两只鞋和片源边界，最后导出透明 WebP/PNG 序列及独立首帧海报。人物按需要用 Multiply 与底色合成，避免预先把背景颜色画进人物。
4. **建立视觉层。** 纸纹底图、色块、人物、阴影、文字分别成层；为桌面和手机定义独立布局。扩张圆形使用同一物理半径计算横纵尺寸，防止手机上变成椭圆。
5. **接入播放器和场景状态。** 输入事件只发出「上一页 / 下一页 / 指定页」请求；状态机负责防重复触发、加载、转场、播放、定格和返回。当前场景与下一场景预加载，远处场景按需加载。
6. **做可视调整。** 在画布上拖位置，在属性栏调整大小、层级、文案、配色；在时间轴调整轨道的开始、结束与缓动。桌面和手机分别预览，并允许覆盖个别布局值。
7. **验收与发布。** 至少检查首帧、中间帧、尾帧、完整转场、反向翻页、手机触摸、慢网加载、双语文本和联系入口。记录本地构建、浏览器预览、线上部署三种不同的验证结果。

## 3. 工作台应该长什么样

```text
左栏：页面顺序 / 场景 / 图层 / 素材
中间：可拖拽画布（桌面、手机、不同宽高预设）
右栏：选中对象的文字、色彩、材质、尺寸、位置、层级、交互
下栏：时间轴（旧页面离场、底色展开、人物逐帧、文字逐段出现）
顶栏：预览、撤销、保存版本、导出、发布
```

可复用的项目数据分五层：

- **主题**：品牌字体、颜色、纹理、按钮和语言。
- **场景**：有序页面列表、背景、文案、导航入口；增删或重排一页只改列表。
- **图层**：每个人物/阴影/标题的素材、锚点、尺寸、透明度、混合模式和桌面/手机位置。
- **动画**：离场、进入、逐帧和文字的独立轨道；提供斜向波浪、中心圆扩张、平移、淡入等预设及起点、方向、时长、缓动参数。
- **运行**：滚轮/触摸阈值、下一页预加载、加载失败回退、减少动态效果偏好、媒体预算。

上传视频后的向导应显示原片与预览：选起止帧 → 标出人物和地面 → 确认是否保留原影子 → 自动生成固定尺寸的序列 → 逐帧检查边缘 → 压缩并显示总大小。自动去背、补头顶或修影子需要人工确认，不能默默覆盖源文件。

## 4. 使用示例配置

`templates/scroll-story.example.json` 是「首页 + 三段内容」的四屏**未来格式草案**，说明成熟工作台需要保存的数据结构，不包含 SIX 的实际媒体或发布凭据。它不能直接导入当前版本。`media` 中的路径只是占位；未来工作台在导入时应验证文件存在、帧数一致、尺寸一致，并保存源视频与生成结果的对应关系。

工作台的最小可用版本按这个顺序建设：

1. **数据驱动播放器**：把现有固定四场景、固定转场改为读取有序 `scenes`；支持桌面/手机布局、页面切换和文字。
2. **浏览器编辑器**：新增/删除/排序页面，编辑主题、图层、文案和转场预设；保存项目 JSON 与历史版本。现有 SIX 本地编辑器仅能调首页少量图层和文案，可作为拖拽交互的起点。
3. **媒体工作流**：导入视频、选择动作范围、生成统一画幅的帧与海报、逐帧检查、按项目预算导出。自动分割失败时允许手动替换帧。
4. **发布与协作**：静态包导出已实现；账户、预览链接、版本回退和一键发布仍待建设。发布前单独确认媒体许可和上传范围。

Frameflow 已支持更换人物帧、配色、文字、页面数量和四种过场预设，并能导出独立静态网页 ZIP；上面的多图层时间轴和自动修帧仍是后续方向。仅有配置示例并不等于这些能力已经上线。

## 5. 每次交付的检查清单

- [ ] 场景列表与点击入口、滚动顺序一致；向上可以返回。
- [ ] 动画开始与结束的底色覆盖整个屏幕，没有残留三角、白边或遮挡层。
- [ ] 每段人物序列的画布尺寸统一；首尾帧衔接自然；头、双脚、影子完整。
- [ ] 人物加载时有海报或首帧，播放没有空白和明显停顿；其他页面不抢首屏带宽。
- [ ] 手机正竖屏和窄横屏文字均可读完，圆形仍为正圆，人物不盖住按钮。
- [ ] 点击、滚轮、触摸和键盘入口可用；尊重系统减少动态效果设置。
- [ ] 构建通过；在浏览器实际播放；发布后检查真实 URL，分别记录结果。
